# Procédure de réponse aux incidents data

Un incident est ouvert lorsqu’un pipeline critique échoue, lorsqu’une donnée sensible est exposée ou lorsqu’un indicateur publié est matériellement erroné. La personne qui détecte le problème consigne l’heure, le périmètre et l’impact connu.

Pour un incident de sévérité élevée, le responsable de service est prévenu dans les trente minutes. Une mise à jour de situation est partagée toutes les deux heures jusqu’au retour à un fonctionnement nominal.

La clôture exige une analyse de cause, une action corrective et une action préventive proportionnée au risque. Le post-mortem est revu lors du point fiabilité hebdomadaire.
